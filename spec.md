# Specification: Учебный трекер

## 1. Управление задачами

### Requirement: Добавление задачи

Система MUST позволять добавлять учебные задачи с названием
и количеством часов.

- Название после trim MUST быть непустым.
- Часы MUST быть числом от 0.5 до 24 включительно.
- Часы MUST изменяться с шагом 0.5.
- Пустое значение часов MUST NOT трактоваться как 0.
- Новая задача MUST иметь уникальный id.
- Новая задача MUST иметь done=false.
- Некорректная задача MUST NOT добавляться.
- При ошибке MUST отображаться сообщение рядом с полем.
- При ошибке введённые значения формы MUST сохраняться.

#### Scenario: Добавление корректной задачи

WHEN пользователь вводит непустое название и допустимое количество
часов и подтверждает добавление

THEN задача добавляется в список
AND её состояние done равно false
AND форма очищается после успешного добавления.

#### Scenario: Пустое название

WHEN пользователь вводит пустое название или название,
состоящее только из пробелов

THEN задача не добавляется
AND отображается ошибка рядом с полем названия
AND введённые значения формы сохраняются.

#### Scenario: Пустые часы

WHEN пользователь не вводит значение часов

THEN задача не добавляется
AND отображается ошибка рядом с полем часов
AND введённые значения формы сохраняются.

#### Scenario: Недопустимые часы

WHEN пользователь вводит отрицательное число, число меньше 0.5,
число больше 24 или число, не соответствующее шагу 0.5

THEN задача не добавляется
AND отображается ошибка рядом с полем часов
AND введённые значения формы сохраняются.

## 2. Удаление задач

### Requirement: Удаление задачи

Система MUST позволять удалять существующие задачи.

#### Scenario: Удаление задачи

WHEN пользователь удаляет задачу

THEN задача удаляется из данных
AND список обновляется
AND суммарные часы и прогресс пересчитываются.

## 3. Выполнение задач

### Requirement: Переключение done

Система MUST позволять переключать состояние done
между true и false.

#### Scenario: Отметка задачи выполненной

WHEN пользователь отмечает задачу выполненной

THEN done становится true
AND прогресс пересчитывается.

#### Scenario: Снятие отметки выполнения

WHEN пользователь снимает отметку выполнения

THEN done становится false
AND прогресс пересчитывается.

## 4. Фильтрация

### Requirement: Фильтр списка

Система MUST поддерживать фильтры:

- Все.
- Активные.
- Готовые.

Фильтр MUST изменять только отображаемый список.

Фильтр MUST NOT изменять исходные данные задач,
суммарные часы или прогресс.

#### Scenario: Фильтр активных задач

WHEN включён фильтр «активные»

THEN отображаются только задачи с done=false
AND прогресс остаётся 25% при исходных данных.

#### Scenario: Фильтр готовых задач

WHEN включён фильтр «готовые»

THEN отображаются только задачи с done=true
AND итоговые часы и прогресс рассчитываются по всем задачам.

#### Scenario: Фильтр всех задач

WHEN включён фильтр «все»

THEN отображаются все существующие задачи.

## 5. Итоги и прогресс

### Requirement: Суммарные часы

Система MUST рассчитывать суммарное количество часов
по всем задачам независимо от фильтра.

### Requirement: Прогресс выполнения

Система MUST рассчитывать прогресс по формуле:

round(100 * сумма часов выполненных задач /
сумма часов всех задач).

Если задач нет или суммарное количество часов равно 0,
прогресс MUST быть равен 0%.

Система MUST NOT отображать NaN или Infinity.

#### Scenario: Начальное состояние

WHEN трекер запускается с исходными задачами

THEN суммарное количество часов равно 8
AND выполнено 2 часа
AND прогресс равен 25%.

#### Scenario: Практика выполнена

WHEN задача «Практика» отмечена выполненной

THEN выполнено 6 часов из 8
AND прогресс равен 75%.

#### Scenario: Все задачи удалены

WHEN все задачи удалены

THEN суммарное количество часов равно 0
AND прогресс равен 0%.

## 6. Интерфейс

### Requirement: Адаптивность и доступность управления

Система MUST обеспечивать читаемость интерфейса при ширине 390 px
без горизонтальной прокрутки.

Поля и кнопки MUST иметь понятные подписи.

Ошибки валидации MUST отображаться рядом с соответствующими полями.

#### Scenario: Узкий экран

WHEN приложение отображается при ширине 390 px

THEN интерфейс остаётся читаемым
AND горизонтальная прокрутка не появляется
AND поля и кнопки имеют понятные подписи.

## 7. Автономность

### Requirement: Работа без внешних зависимостей

Система MUST работать без CDN, внешних библиотек и API-ключей.

#### Scenario: Автономный запуск

WHEN пользователь открывает приложение

THEN приложение не требует подключения внешних библиотек,
CDN или API-ключей для своей работы.

## 8. Необязательное улучшение: localStorage

### Requirement: Локальное сохранение

Система MAY сохранять задачи в localStorage.

Если localStorage недоступен, система MUST продолжать работу
в памяти и MUST отображать понятное сообщение о недоступности
хранилища.

#### Scenario: Хранилище доступно

WHEN localStorage доступен

THEN задачи могут сохраняться локально
AND восстанавливаться при повторном запуске.

#### Scenario: Хранилище недоступно

WHEN localStorage недоступен

THEN приложение продолжает работу в памяти
AND пользователь получает понятное сообщение.
